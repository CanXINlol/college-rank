# 从研究 MVP 到全球数据服务

## 当前交付边界

可运行网站、可调排名算法、12 位真实人才的引用数据、Wikidata 增量发现采集器、GitHub 工作流与算法测试。官方目录的全量抽取和全球身份图谱尚未完成。

## 下一阶段

1. **机构主数据**：接入 ROR，记录大学/研究院/院系的父子关系、别名、合并沿革和规范域名。大学榜与研究机构榜需明确聚合层级。
2. **目录适配器**：优先覆盖公开 JSON API/结构化人员目录，按域名配置限速、robots 与更新策略，解析官方主页与 CV。不同页面结构独立适配与回归测试，不绕过认证或站点限制。
3. **人员消歧**：ORCID / Wikidata ID 与来源组合、姓名/机构/时间一致性验证、冲突队列；不可凭姓名强行合并。
4. **时间与状态**：建立任职开始/结束事件、来源更新时间、有效期、历史快照。留职、荣休、访问、联合任职与在读博士分别处理。
5. **奖项数据**：官方获奖名单适配器；奖项事件归属、共享奖项计分策略；IEEE Milestone 以机构成就事件单独核验。
6. **覆盖报告**：按机构报告“目录已发现人数/已解析/学历可确认/在职可确认”；没有完整目录分母时不显示百分比。
7. **统计分析**：学科/年代标准化、学校规模归一化、跨国与历史偏差、Bootstrap 置信区间、权重敏感性；先发布覆盖数据，再解释排名。
8. **生产规模**：任务队列、PostgreSQL、对象存储、分布式采集、增量图计算、服务端图查询。现有 Python 标准库与浏览器全图重算面向小型研究数据集。

“全世界所有 faculty”是持续维护的数据工程目标，无法用现有开放数据或一次爬取保证完整。实际发布应始终标注采集日期、来源、覆盖范围与失败情况。
